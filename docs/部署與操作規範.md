## 一、適用對象、相容性邊界與環境準備

### 1. 硬體與韌體版本釘選（務必核對）
- **適用機型與韌體**：**Sony ILCE-6400（A6400）FW 2.00**。
- 原生 UI 接駁（[`camera/native_film_ui_trial3.c`](../camera/native_film_ui_trial3.c)、[`camera/native_ui_load_guard.c`](../camera/native_ui_load_guard.c)）與磁碟掃描（[`camera/film_native_command.c`](../camera/film_native_command.c)）依賴 FW 2.00 的確定符號／位址（`im.elf`、`libObj.so`、`viewUnified2.so`、`libInfraFsys.so`）。
- **嚴禁強行套用到 A6000／A6100／A6600 或不同韌體版本**；程式內建位移與位元組指紋比對，不符會自動拒絕載入，切勿刪除檢查。

### 2. 跨平台編譯與 USB 部署環境（Windows / Linux / macOS 通用）

- **Linux（Ubuntu / Debian / Orange Pi，最推薦）**：
  ```sh
  sudo apt-get update
  sudo apt-get install -y \
    git make python3 python3-usb libusb-1.0-0 \
    gcc-arm-linux-gnueabihf g++-arm-linux-gnueabihf
  ```
- **macOS**：
  - **編譯階段**：使用 Homebrew 工具鏈（`brew install messense/macos-cross-toolchains/arm-linux-gnueabihf` 或任何 `arm-linux-gnueabihf-gcc/g++`），或直接透過 Docker (`--platform linux/amd64` / `ubuntu` 容器安裝 `gcc-arm-linux-gnueabihf g++-arm-linux-gnueabihf make python3`) 執行 `sh tools/build_v3_clite.sh` 產出 `build-v3-clite/local-boot-package`。
  - **USB 部署階段**：於 macOS 原生 Python 執行 `brew install libusb` + `pip3 install pyusb`，再用 `python3 tools/pmca_deploy_v3_clite.py`（macOS 下使用 USB 大容量儲存或 MTP 皆可；若被系統佔用 Mass Storage，可切換相機為 **MTP 模式**）。
- **Windows**：
  - **編譯階段**：於 **WSL2 (Ubuntu)** 安裝 `gcc-arm-linux-gnueabihf g++-arm-linux-gnueabihf make python3`，或使用 Docker Ubuntu 容器執行 `sh tools/build_v3_clite.sh` 產出 `local-boot-package`。
  - **USB 部署階段**：可直接在 Windows 原生 Python 安裝 `pyusb`＋`libusb`（或使用 Zadig 將相機切為 libusb-win32 / WinUSB，或透過 `usbipd-win` 把相機 USB 轉發給 WSL2 後在 WSL2 內執行 `sudo python3 tools/pmca_deploy_v3_clite.py`）。

取得連線部署工具 `Sony-PMCA-RE`：
```sh
git clone https://github.com/ma1co/Sony-PMCA-RE.git /path/to/Sony-PMCA-RE
```

### 3. 相機設定與開機掛勾前置條件
1. 相機電源保持滿電（建議電量 > 50%），記憶卡已插入相機。
2. 開啟相機 `MENU` → `設定（工具箱）` 第 4 頁 → **`USB 連線`** 設為 **`大容量儲存（Mass Storage）`**（若提示找不到裝置亦可切 **`MTP`**）。
3. 確認目標機已具備開機掛勾基礎環境（即 `/etc/ld.so.preload` 指向 `/tmp/a6400-autoexec.so`，此掛勾負責在開機初期啟動 `/tmp/autoexec.sh`）。

### 4. 從目標 A6400 合法拉取 4 個原廠輸入檔（公開倉庫不含 Sony 原廠二進位）
使用 `Sony-PMCA-RE` 進入相機 `serviceshell` 後，將下列相機端檔案拉取至開發機（可透過 PMCA shell `pull` 或轉碼複製）：
- **`/lib/libc-2.11.2.so`** 與 **`/lib/libdl-2.11.2.so`** → 存入本機 `/path/to/camera-libs/`
- **`/usr/bin/mpr_monio.elf`** → 存為 `/path/to/camera-mpr_monio.elf`（建置腳本預設雜湊釘選為 FW 2.00 原版 `300ed9c5a90dc26c3390b5fdd85c5a6e4d5f26e24c6022aa56832f83a47a96bf`）
- **`/usr/bin/mwf_monio.elf`** → 存為 `/path/to/camera-mwf_monio.elf`

同時可在 `serviceshell` 先行確認目標機掛勾與 Flash `/tmp` 空間：
```sh
/bin/busybox cat /etc/ld.so.preload
/bin/busybox ls -la /tmp /tmp/a6400-autoexec.so
```
> 若目標機是**全新原廠、尚未安裝開機掛勾**，請一併從相機拉取 `/usr/lib/libAK8975.so`，使用本倉庫內建的 [`tools/build_autoexec_hook.py`](../tools/build_autoexec_hook.py) 從零產生含三重急停（`/mnt/disable_hook`、`/mnt/disable.txt`、`/tmp/disable_hook`）與 `/tmp_bt/ae.lock` 的 `a6400-autoexec.so`：
> ```sh
> python3 tools/build_autoexec_hook.py /path/to/libAK8975.so ./build-v3-clite/a6400-autoexec.so
> ```
> 先將 `/tmp/a6400-autoexec.so`（`0755`）與 `/tmp/autoexec.sh`（透過下方 `pmca_deploy_v3_clite.py`）寫入相機並核對 `sha256sum` 後，再備份並寫入 `/etc/ld.so.preload`（內容為 `/tmp/a6400-autoexec.so`）。

### 步驟 2：執行一鍵編譯打包（[`tools/build_v3_clite.sh`](../tools/build_v3_clite.sh)）

1. 編譯 10 膠片 JPEG Worker → `a6400-film-job.elf`（啟用 `-Wl,--gc-sections -Wl,-s` 精簡體積）
2. 編譯持久型 V3 CLite 原生 UI 與載入 payload（`A6400_TRIAL_MS=0`、`A6400_DISPLAY_MS=20000`、`UI_MODULE_PATH=/tmp_bt/a6400-film-ui-v3-persist.so`）

6. 編譯 UI 載入保護程式（`a6400-ui-load-guard.elf`）並產出 `check-persist.req`、`install-persist.req`、`remove-persist.req`

8. 編譯背景掃描守護行程（`a6400-film-capture-daemon.elf`，`FILM_CAPTURE_PERSISTENT=1`）
9. 產出 `runtime-artifacts.json` 並組裝驗證 `local-boot-package/`（包含 `bootstrap-local.sh` 與 `persistent/a6400-film-boot-v15.tar`，體積限制 ≤ `196,608` B）

## 四、寫入目標 A6400 與冷開機驗收

> **安全鐵律**：寫入過程只寫入檔案（data-only），**禁止在 PMCA USB shell 內直接熱執行 daemon 或掛載 SD**，一律交由拔線斷電冷開機自然啟動。

### 步驟 1：記憶卡準備（必做）
將相機要拍攝使用的 SD 記憶卡放入電腦或於相機端準備好，**在記憶卡最上層根目錄建立空資料夾 `/A6400/TEST/`**（與 `/DCIM/` 並列；所有套色成品 `Fxxxxxxx.JPG` 會安全輸出至此資料夾，絕不覆蓋 `DCIM` 原片）。

### 步驟 2：一鍵透過 PMCA 安全備份與刷入（[`tools/pmca_deploy_v3_clite.py`](../tools/pmca_deploy_v3_clite.py)）
確認相機開機並以 USB 連接電腦後執行：
```sh
sudo python3 tools/pmca_deploy_v3_clite.py \
  ./build-v3-clite/local-boot-package \
  --pmca-dir /path/to/Sony-PMCA-RE
```
腳本會自動完成下列防護與寫入動作：
1. 確認 `/etc/ld.so.preload` 與 `/tmp/a6400-autoexec.so` 存在，否則中止。
2. 若目標相機已有 `/tmp/autoexec.sh` 或 `/tmp/a6400-film-boot-v15.tar`，先複製成對備份為 `/tmp/autoexec.sh.pre-v3c-backup` 與 `/tmp/a6400-film-boot-v15.tar.pre-v3c-backup`。
3. 透過 Base64 分塊傳輸到 RAM 暫存 `/tmp_bt/v3c_up`，核對 `.tgz`、`.sh`、`.tar` 與 tar 內 **全部 11 個解包元件的 SHA-256**，並以 `/bin/sh -n` 檢查啟動腳本語法。
4. 先將檔案寫到 `/tmp/*.new` 執行 `sync` 後再原子 `mv` 覆蓋 `/tmp/a6400-film-boot-v15.tar`（`0644`）與 `/tmp/autoexec.sh`（`0755`），清除暫存與 `/tmp/disable_hook` 後再度執行 `sha256sum` 雙向驗證。
5. 成功輸出：`V3_CLITE_DEPLOY_OK package=<id>`。

### 步驟 3：完全斷電冷開機
1. 等待電腦端指令完全結束並回到提示字元。
2. **拔除相機 USB 傳輸線**。
3. 將相機電源開關撥至 `OFF`，等記憶卡存取燈完全熄滅後，**取出電池約 10 秒再裝回並開機**。

### 步驟 4：首輪冷開機實測驗收
1. 開機後靜待約 **35–40 秒**（讓開機 Guard 檢查與基線 DCF 掃描完成）。
2. **先用手指輕觸相機觸控螢幕並放開一次**（觸發一鍵掛入常駐 UI 模組）。
3. 確認畫面為正常拍攝 Live View 待機畫面後，**同時長按 `MENU ＋ 放大鏡（C2/刪除旁放大鏡鈕）` 約 2 秒**。
4. 驗收選單功能：
   - 頂部顯示 `A6400 V3 CLite | 關閉`，預設為 `關閉`。
   - 點擊 `LUT 濾鏡: 關閉` → 切換為暖琥珀高亮 `LUT 濾鏡: 開啟`。
   - 點擊 `膠片風格: ...` → 切換到第 1 頁（presets `0..4`）或點擊左下角 `下一頁 >` 進入第 2 頁（presets `5..9`，例如 `Classic Chrome`），選中項目高亮並自動返回主選單。
   - 點擊右下角 `關閉`（或等待 20 秒自動隱藏）後再長按 `MENU ＋ 放大鏡` 重開，確認設定維持保留。
5. 驗收實拍套色：
   - 保持 `LUT 濾鏡: 開啟`，拍攝一張 JPEG（建議畫質 `FINE` 精細）。
   - **等待約 22–25 秒**（期間勿切換濾鏡開關或立即再拍），隨後把記憶卡插入電腦檢查 `/A6400/TEST/` 目錄是否新增對應的 `Fxxxxxxx.JPG` 成品圖，且 `DCIM` 原片完整無損。

## 五、日常使用規範與安全邊界（必讀）

| 項目 | 規範與硬性上限 | 說明 |
| --- | --- | --- |
| **開機待機** | 開機後先等 **30–40 秒** | 開機 Guard（約 1.7s）與背景守護行程需要時間等待系統執行緒穩定與建立初始檔案基線。 |
| **叫出選單條件** | **必須先輕觸並放開螢幕一次**，再長按 `MENU ＋ 放大鏡` 2 秒 | 若從未碰過螢幕就直接長按組合鍵，UI 模組尚未載入，選單不會出現。 |
| **畫面待機位置** | 建議僅在 **正常拍攝 Live View 畫面** 召喚與點擊選單 | 選單採事件透傳設計，若在原廠選單／回放畫面重疊點擊，背景層同時會收到觸控事件。 |
| **單夾張數上限** | 最新 `DCIM` 資料夾內 `.JPG` 須 **< 128 張** | 僅計 `.JPG`（不含 `.ARW`）。接近 120 張時請於相機選單「建立新資料夾」或切換日期資料夾，滿 128 張會觸發安全保護停止掃描。 |
| **單檔大小上限** | 待處理 `.JPG` 須 **< `16,711,680` bytes（`15.94 MiB`）** | `FINE` 畫質幾乎不超標；高 ISO 極複雜場景若 `X.FINE` 超過此上限，該張會自動略過處理，原圖不受損。 |
| **寫入間隔保護** | 拍攝開啟濾鏡的照片後，請等 **22 秒左右** 不要馬上切換 LUT 開關 | 若處理中切換 `開啟／關閉` 或更換膠片風格，背景驗證階段會自動中止並取消該筆寫入。 |
| **關機記憶** | 關機／拔電池後重設為 `關閉` | 設定保存在 RAM，不寫入相機 Flash，避免開機自動套色干擾一般拍攝。 |
| **未插卡保護** | 開機 60 秒內無 SD 卡將安全退出守護行程 | 不會當機；若超過 60 秒才插卡，需重開機才會重新啟動背景套色。 |

## 六、除錯日誌與常見異常排解

透過 USB 進入 `Sony-PMCA-RE` 的 `serviceshell` 後，所有執行期記錄都位於 RAM（`/tmp_bt`），關機自動清空：

```sh
/bin/busybox cat /tmp_bt/a6400-film-boot.log
/bin/busybox cat /tmp_bt/a6400-film-capture.runtime.log
/bin/busybox cat /tmp_bt/a6400-film-capture.job.log
/bin/busybox cat /tmp_bt/a6400-film-ram-job.log
```

- **現象 1：長按 `MENU + 放大鏡` 沒出現選單**
  - 先確認是否已「**輕觸並放開螢幕一次**」。
  - 檢查 `/tmp_bt/a6400-film-boot.log` 與 `/tmp_bt/a6400-film-runtime.log` 是否出現 `FILM_RUNTIME_READY`；若出現 `GUARD_FAIL`，核對韌體是否為 A6400 FW 2.00 與 `camera-libs` 是否來自該機。
- **現象 2：選單可開且已設為 `開啟`，但拍完 `/A6400/TEST/` 沒有出現新圖**
  - 檢查記憶卡根目錄是否已建立 **`/A6400/TEST/`** 資料夾（本版不自動新建外層資料夾，缺少目標夾或超出 128 張／15.94 MiB 上限都會略過）。
  - 檢視 `/tmp_bt/a6400-film-ram-job.log` 與 `/tmp_bt/a6400-film-capture.job.log` 的 `result=` 與 `reason=`。
- **現象 3：未插 SD 卡或卡滿**
  - `/tmp_bt/a6400-film-capture.runtime.log` 若超過 60 秒找不到 `/dev/mmca` 會顯示安全退出的紀錄，插卡後重開機即可。

## 七、三層緊急停用與回滾步驟（絕對不會變磚）

1. **第一層（免接線 SD 卡急停）**：
   - 拔出 SD 卡用電腦在根目錄建立空檔案 `disable_hook`（或 `disable.txt`），插回相機重開機，開機載入器看到 `/mnt/disable_hook` 會立即跳過所有外掛，100% 恢復原廠。
2. **第二層（Flash 標記臨時停用，保留檔案）**：
   - 透過 PMCA `serviceshell` 執行 `touch /tmp/disable_hook`，重開機即停用（日後 `rm /tmp/disable_hook` 即可恢復）。
3. **第三層（完整還原部署前備份）**：
   - 若部署前原本已有檔案，可透過 PMCA `serviceshell` 成對還原：
