## 快速一鍵總覽（從 GitHub 原始碼建置與部署）

```sh
# 步驟 1：取得公開原始碼並通過電腦端測試與公開檔案檢查
git clone https://github.com/PCIEARIA/A6400-Extra-Menu.git
cd A6400-Extra-Menu
python3 -m unittest discover -p 'test_*.py' -v
python3 tools/check_public_tree.py

# 步驟 2：一鍵交叉編譯並打包（有無 assets/a6400-charo-shutter.pcm 皆可直接建置）
sh tools/build_v3_clite.sh \
  /path/to/camera-libs \
  /path/to/camera-mpr_monio.elf \
  /path/to/camera-mwf_monio.elf \
  ./build-v351-fast-sp

# 步驟 3：相機接上 USB（Mass Storage），自動準備依賴、修補全新機身掛勾、寫入並雙向 SHA-256 校驗
sudo python3 tools/pmca_deploy_v3_clite.py \
  ./build-v351-fast-sp/local-boot-package
```

若使用 **Releases 預編譯一鍵懶人包（`A6400-V3.5.1-Fast-SP-OneClick.zip`）**，已內附 `Sony-PMCA-RE/` 與預編譯包體（另附 `v3.1-universal-rollback/` 備援回滾包），可直接參考下方的「記憶卡與 Windows / macOS 前置條件」。

## 一、適用對象、相容性邊界與環境準備

### 1. 硬體與韌體版本檢查（務必在相機端核對）
- **適用機型與韌體**：**Sony ILCE-6400（A6400）FW `Ver. 2.00`**。
  - 請在相機螢幕打開 **`MENU` → `設定（工具箱）` → `版本`** 親自確認顯示 `Ver. 2.00`（Windows USB 大容量儲存模式僅露出磁碟機，無法從 PC 讀卡機判斷韌體版本）。
- **硬體架構釘選**：實機 CPU 為 ARMv7 Cortex-A5（`CPU part: 0xc05`、`vfpv3d16` / `vfpv4`，**無 NEON SIMD**），交叉編譯僅可使用 `-mcpu=cortex-a5 -mfpu=vfpv3-d16 -mfloat-abi=hard`，嚴禁擅自啟用 `-mfpu=neon`。
- **嚴禁跨機型套用**：UI 接駁（[`camera/native_film_ui_trial3.c`](../camera/native_film_ui_trial3.c)、[`camera/native_ui_load_guard.c`](../camera/native_ui_load_guard.c)）對 FW 2.00 符號與記憶體進行指紋驗證，不符會自動拒絕載入，切勿套用到其他機身或韌體。

### 2. 部署電腦必要條件（Windows / Linux / macOS）
- **Python 3.8 以上 + 管理員權限**：
  - **Linux（Ubuntu / Debian / Orange Pi）**：需 `python3`、`python3-usb`、`libusb-1.0-0` 與 `sudo`（或對應 udev 規則）；編譯另需 `gcc-arm-linux-gnueabihf`、`g++-arm-linux-gnueabihf`、`make`。
  - **macOS**：安裝官方 Python 3（非僅 Xcode stub）及 `libusb`／`pyusb`，並以 `sudo` 存取 USB；交叉編譯可透過 Homebrew 工具鏈或 Linux 容器進行。
  - **Windows**：須具備 **可用之 Python 3.8+**（非 0-byte Microsoft Store 佔位符）、**系統管理員權限**以執行 **Zadig**（將裝置 `ILCE-6400` / `Sony DSC` 替換為 `libusb-win32`；注意切換成服務模式後若裝置重新枚舉，需對新裝置再替換一次驅動）、以及可安裝 `pyusb`、`libusb-package`、`pycryptodomex`、`axmlparserpy==0.0.4`、`pyyaml`、`asn1crypto`、`certifi`、`tlslite-ng`、`comtypes`、`pywin32` 等 Python 相依套件的網路或離線 wheel 環境。

### 3. 相機與記憶卡準備（⚠️ 必設「Bluetooth 開啟」）
1. 相機保持滿電（建議 > 50%），插好測試記憶卡。
2. **【必做前置設定】開啟相機 Bluetooth（否則冷開機不會掛載 `/tmp_bt` 與觸發預載掛勾！）**：
   - 進入相機 **`MENU` → `網路（綠色地球圖示）` → `Bluetooth 設定` → `Bluetooth 功能` → 設為 `開`**，並確認 **`飛航模式` = `關`**。
   - *原理解釋*：Sony A6400 採用 `/system/sabin/ssboot.bin`（`warm.mode=2`）快照休眠架構恢復 `im.elf`，因此 `im.elf` 本身不會走 `execve()` 與 `/etc/ld.so.preload`；真正會在冷開機 ~14 秒執行 `mount -t tmpfs none /tmp_bt` 並 `execve()` 觸發 `/etc/ld.so.preload` 的，是藍牙服務 `startBTCore.sh → /usr/bin/bsa_server`。若原廠預設藍牙為「關」，`/tmp_bt` 會停留在唯讀的 `/dev/nflasha7` rootfs 上，且整次開機不會觸發外掛！
3. 開啟相機 `MENU` → `設定` 第 4 頁 → **`USB 連線`** 設為 **`大容量儲存（Mass Storage）`**。
4. **記憶卡檔案系統與資料夾建立（支援 FAT32 與 exFAT）**：
   - 開機期間 `bootstrap-local.sh` 不觸碰記憶卡（`native_sd_read=0`），拍攝後全程透過 Sony 原生 `mwf_monio` `IFSYS` 讀寫 `B:`/`A:`，因此 **`FAT32` 與大容量 `exFAT`（如 64GB / 128GB SDXC）皆可直接正常使用，無需刻意轉成 FAT32**。
   - **唯一必做項目**：請先在記憶卡最上層建立空資料夾 **`/A6400/TEST/`**（與 `/DCIM/` 並列）。

### 4. 從 A6400 拉取 4 個原廠編譯輸入檔（僅自行從源碼編譯時需要）
透過 `Sony-PMCA-RE` 進入 `serviceshell` 後，拉取下列原廠檔案至開發機（不可提交到 Git）：
- `/lib/libc-2.11.2.so` 與 `/lib/libdl-2.11.2.so`
- `/usr/bin/mpr_monio.elf`（FW 2.00 SHA-256：`300ed9c5a90dc26c3390b5fdd85c5a6e4d5f26e24c6022aa56832f83a47a96bf`）
- `/usr/bin/mwf_monio.elf`

## 三、寫入目標 A6400 與冷開機驗收

> **安全鐵律**：寫入過程只寫檔案（data-only），**禁止在 PMCA USB shell 內直接熱執行守護行程或掛載 SD 卡**，一律靠拔線斷電冷開機啟動。

1. 相機接上 USB 後執行部署腳本（`oneclick_deploy.py` 或 `tools/pmca_deploy_v3_clite.py`）。
   - 若目標相機 `/etc/ld.so.preload` 尚未指向非空 `/tmp/a6400-autoexec.so`，腳本會即時讀取該機 `/usr/lib/libAK8975.so`，嚴格驗證 `.text == 0x988`、`.rodata` 與 `.dynamic DT_NULL` 後修補，不符即中止。
   - 既有 `/tmp/autoexec.sh` 與 `/tmp/a6400-film-boot-v15.tar` 會先保留 `.pre-v3c-backup`，透過原子搬移＋雙向 `sha256sum` / `openssl dgst -sha256` 確認後才完成（成功標誌：`ONECLICK_V3_5_1_FAST_SP_DEPLOY_OK` 或 `V3_CLITE_DEPLOY_OK`）。
2. **完全斷電冷開機**：拔掉 USB 線 → 相機關機 → **取出電池 10 秒再裝回開機**。
3. **首輪冷開機驗收**：
   - 開機後等待 **35–40 秒**，**輕觸螢幕並放開一次** → 等約 2 秒。
   - **同時長按 `MENU ＋ 放大鏡` 約 2 秒**叫出浮層卡片（標題顯示 `A6400 3.5.1 SP | 關閉`）：
     - 第 1 列：`LUT 濾鏡: 關閉 / 開啟`
     - 第 2 列：`膠片風格`（可翻頁選擇 10 款預設）
     - 第 3 列：`膠片細節`（進入子選單調節 **顆粒強度 0–3** 與 **底片光暈 開/關**，或一鍵恢復預設）
     - （若編譯時含私人音效）第 4 列：`快門聲`
     - 左下角：`畫質: 1.7MP 極速` / `畫質: 6MP 高清`；右下角：`關閉`
   - 建議將相機「**自動檢視 (Auto Review)**」設為 **`關`**，拍照瞬間左下角會顯示橘色 `處理中...` → 完成顯示綠色 `OK 已存SD: ... (FxxxxNNN.JPG)`（`1.7MP` 約 `5.6~8.2 秒`、`6MP` 約 `17.5~21 秒`，依顆粒/光暈與 JPEG 大小而異）。

## 四、日常使用規範與安全邊界

| 項目 | 規範與硬性上限 | 說明 |
| --- | --- | --- |
| **開機待機** | 開機後等 **30–40 秒** | Guard 檢查 `im.elf` 並建立初始 DCF 掃描基線。 |
| **召喚前提** | **先輕觸並放開螢幕一次**，再長按 `MENU ＋ 放大鏡` 2 秒 | 未碰觸過螢幕前 UI 模組尚未在 Appframework 執行緒掛載。 |
| **最新夾張數上限** | 最新 `DCIM` 資料夾內 `.JPG` **< `1,024` 張** | 持久化版本 `MAX_FILES=1024u`（僅計該最新目錄 `.JPG`）。 |
| **單檔大小上限** | 待處理原圖 `.JPG` **< `16,711,680` bytes（`15.94 MiB`）** | `X.FINE` 高雜訊極端圖超過此限制時會安全略過，原圖無損。 |
| **連拍寫卡節奏** | 連拍大圖時建議待前一張存卡完成／左下角綠色提示出現 | 避免在 SD 卡最後 64 KiB 尚未 flush 時觸發掃描導致 `stage=source_size` 安全略過（原片不受影響）。 |
| **關機記憶** | 關機／拔電池後恢復預設關閉 | 全數狀態僅駐留 RAM，不改寫原廠拍攝或選單 NVRAM。 |

## 五、日誌除錯與緊急停用／回滾路徑

所有運行日誌都在 `/tmp_bt/`（斷電即清），可經 USB PMCA `serviceshell` 檢視：
```sh
/bin/busybox cat /tmp_bt/a6400-film-boot.log
/bin/busybox cat /tmp_bt/a6400-film-capture.runtime.log
/bin/busybox cat /tmp_bt/a6400-film-capture.job.log
/bin/busybox cat /tmp_bt/a6400-film-capture.manifest
```

### 停用與回滾路徑（誠實邊界說明）

- **`/etc/ld.so.preload` 急停旗標與適用範圍**：開機掛勾 `a6400-autoexec.so` 會依序檢查 `/mnt/disable_hook`、`/mnt/disable.txt` 與 `/tmp/disable_hook`；但市售 A6400 記憶卡由原生 `IFSYS` 管理，通常並未在 Linux Boot 階段自動掛載於 `/mnt`。因此**最可靠、保證生效的停用／切換／回滾方式，仍是透過 USB 進入 PMCA 服務模式**操作：
  1. **臨時停用外掛（保留檔案）**：於 PMCA `serviceshell` 執行 `/bin/busybox touch /tmp/disable_hook && /bin/busybox sync`，拔線冷開機後即完全恢復原廠行為（日後 `rm /tmp/disable_hook` 可恢復）。
  2. **一鍵回滾穩定版本**：將 USB 接回電腦，以一鍵包內附的 `v3.1-universal-rollback/local-boot-package`（`package=5376263138a4a46c`）或上一版穩定包重跑 `oneclick_deploy.py` / `pmca_deploy_v3_clite.py`。
  3. **還原備份**：於 `serviceshell` 成對還原 `.pre-v3c-backup`：
     ```sh
     /bin/busybox cp -p /tmp/autoexec.sh.pre-v3c-backup /tmp/autoexec.sh
     /bin/busybox cp -p /tmp/a6400-film-boot-v15.tar.pre-v3c-backup /tmp/a6400-film-boot-v15.tar
     /bin/busybox chmod 755 /tmp/autoexec.sh && /bin/busybox chmod 644 /tmp/a6400-film-boot-v15.tar
     /bin/busybox sync
     ```
  4. **Windows 使用者刷完恢復一般讀卡功能**：於「裝置管理員」找到已換成 `libusb-win32` 的相機裝置 → 按右鍵「解除安裝裝置」並勾選「刪除此裝置的驅動程式軟體」→ 重插相機即可恢復標準 `USBSTOR` 讀卡機。
