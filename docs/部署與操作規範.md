# A6400 Extra-Menu 部署與日常操作規範

> **閱讀前提**：本文件整理自實機驗證流程，說明如何從本倉庫原始碼為另一台同型號 **Sony ILCE-6400** 建置並部署選單與背景協調架構，以及實機日常使用時的注意事項。部署前請先閱讀 [授權說明](授權說明.md)、[功能狀態與限制](功能狀態.md) 與 [編譯與目錄說明](編譯與目錄.md)。

---

## 一、適用對象與相容性前提（必讀）

1. **硬體與韌體版本釘選**
   - 本專案的原生 UI 接駁（`camera/native_film_ui_trial3.c`、`camera/native_ui_load_guard.c`）與動態磁碟識別（`camera/film_native_command.c`）依賴特定版號 Sony A6400 韌體的記憶體位址與系統函式庫（例如 `im.elf`、`libObj.so`、`viewUnified2.so`、`libInfraFsys.so`）。
   - **不可直接套用到不同型號相機（如 A6000/A6100/A6600）或不同韌體版本**；建置腳本內建雜湊與位址檢查，若與目標機身不符會自動拒絕載入，切勿刪除檢查強制寫入。
2. **本機必要外部依賴（公開倉庫不附帶）**
   - 開發／建置主機需安裝 ARM hard-float 交叉編譯器（`arm-linux-gnueabihf-gcc`）與 Python 3.10+。
   - 從目標機合法拉取的相機系統函式庫目錄（含 `libc-2.11.2.so`、`libdl-2.11.2.so`）。
   - 目標機對應版本的原廠 monitor 執行檔：`camera-mpr_monio.elf` 與 `camera-mwf_monio.elf`。
   - 具合法再散布與使用授權的 JPEG 濾鏡處理 worker（公開版不含第三方演算法實作）。
   - 連線部署工具 `Sony-PMCA-RE`（支援 `serviceshell`），以及目標機既有的開機啟動掛勾環境（`/etc/ld.so.preload` + `/tmp/a6400-autoexec.so`）。

## 二、開發機建置與打包流程

### 步驟 1：取得公開原始碼並執行電腦端自檢

```sh
git clone https://github.com/PCIEARIA/A6400-Extra-Menu.git
cd A6400-Extra-Menu
python3 -m unittest discover -p 'test_*.py' -v
python3 tools/check_public_tree.py
```

確認所有單元測試與公開樹檢查全數通過後，再開始交叉編譯。

### 步驟 2：交叉編譯相機端元件（全部為 Build-Only）

假設將所有編譯產物輸出至 `./build/`，相機原廠函式庫位於 `/path/to/camera-libs`：

1. **編譯持久型 V3 CLite 原生 UI 與載入 payload**
   ```sh
   A6400_TRIAL_MS=0 \
   A6400_DISPLAY_MS=20000 \
   UI_MODULE_PATH=/tmp_bt/a6400-film-ui-v3-persist.so \
   sh host-tests/build_ui_trial3.sh build/ui /path/to/camera-libs
   ```
   - 會產出 `build/ui/a6400-film-ui-v3.so`、`build/ui/payload.bin` 與 `build/ui/symbols.txt`。

2. **編譯設定讀取 CLI（須與上一步 UI 嚴格配對）**
   ```sh
   FILM_SETTINGS_PERSISTENT=1 \
   UI_MODULE_PATH=/tmp_bt/a6400-film-ui-v3-persist.so \
   sh host-tests/build_film_menu_job_cli.sh build/menu-job /path/to/camera-libs build/ui
   ```

3. **編譯 UI 停止控制 CLI**
   ```sh
   UI_MODULE_PATH=/tmp_bt/a6400-film-ui-v3-persist.so \
   sh host-tests/build_film_ui_stop_cli.sh build/ui-stop /path/to/camera-libs build/ui
   ```

4. **編譯原生檔案命令橋接器**
   ```sh
   sh host-tests/build_film_native_command.sh build/native /path/to/camera-libs /path/to/camera-mwf_monio.elf
   ```

5. **編譯 UI 載入保護程式與產生 `.req` 請求檔**
   - 依 `camera/native_ui_load_guard.c`（搭配 `camera/native_freeze.h`）編譯出 `a6400-ui-load-guard.elf`，並依 `build/ui/payload.bin` 封裝 `check`（`op=0`）、`install`（`op=1`）與 `remove`（`op=2`）三組請求檔。

6. **釘選 `a6400-film-ram-job.sh` 內部雜湊**
   - 複製 `camera/film_ram_job.sh` 至 `build/a6400-film-ram-job.sh`，將腳本內的佔位符替換為本次實際編譯產物的 64 字元 SHA-256：
     - `__NATIVE_SHA__` ← `build/native/a6400-film-native-command.elf`
     - `__WORKER_SHA__` ← 你的合法 JPEG 處理 worker 執行檔
     - `__SETTINGS_SHA__` ← `build/menu-job/a6400-film-menu-job.elf`

7. **編譯背景掃描守護行程（Capture Daemon）**
   ```sh
   FILM_CAPTURE_PERSISTENT=1 \
   sh host-tests/build_film_capture_daemon.sh \
     build/daemon \
     /path/to/camera-libs \
     build/a6400-film-ram-job.sh \
     build/menu-job/a6400-film-menu-job.elf
   ```

8. **組裝與驗證本地開機套件**
   - 依照 `host-tests/film-runtime-v2-templates/` 結構整理各元件與 SHA-256 至規格 JSON，呼叫 `host-tests/build_film_runtime_package.py` 與本地啟動封裝程序產生最終的 `autoexec.sh` 與 `a6400-film-boot-v15.tar`。
   - 組裝腳本會強制核對 `a6400-film-ram-job.sh` 與守護行程內的元件雜湊是否完全一致，不一致時會直接中止打包。

## 三、寫入目標 A6400 相機與冷開機驗收

> **安全原則**：只做純檔案寫入（data-only），**不要在 PMCA shell 內直接熱啟動 daemon 或載入 UI**，一律交由斷電冷開機自然啟動。

1. **準備 SD 卡輸出資料夾**
   - 在目標相機要使用的記憶卡根目錄預先建立 **`/A6400/TEST/`** 資料夾（供濾鏡成品圖 `Fxxxxxxx.JPG` 寫入，與相機 `DCIM` 原片完全隔離）。
2. **透過 PMCA 備份並寫入 `/tmp/`**
   - 將相機設為大容量儲存／連線模式，在主機執行 `Sony-PMCA-RE` 的 `serviceshell` 進入相機 root shell。
   - 若相機 `/tmp/` 已有舊版檔案，先保留一份成對備份：
     ```sh
     cp /tmp/autoexec.sh /tmp/autoexec.sh.pre-backup
     cp /tmp/a6400-film-boot-v15.tar /tmp/a6400-film-boot-v15.tar.pre-backup
     ```
   - 寫入新的 `/tmp/autoexec.sh`（權限 `0755`）與 `/tmp/a6400-film-boot-v15.tar`（權限 `0644`），並在相機端執行 `sha256sum` 核對與開發機產出完全相同。
3. **正常退出並冷開機**
   - 在 `serviceshell` 輸入 `exit` 等候工具完全退出（出現 `Done`），拔除 USB 傳輸線。
   - 關閉相機電源、等記憶卡存取燈熄滅後，**取出電池約 10 秒再裝回開機**。
4. **首輪功能驗收**
   - 開機後等待約 35–40 秒（待開機 Guard 與基線掃描就緒）。
   - **先輕觸螢幕並放開一次**（觸發載入選單模組），再同時按住 **`MENU ＋ 放大鏡`** 約 2 秒。
   - 確認浮動選單開啟、預設為 `關閉`、可切換狀態與關閉／自動隱藏，且重開選單設定仍保留。

## 四、日常使用操作規範與安全邊界

請遵守以下操作規範，可確保穩定運作且不會觸發保護性停機：

1. **冷開機啟動順序**
   - 開機後請等約 **30–40 秒** 讓後台就緒。
   - 必須**先輕觸並放開螢幕一次**，之後長按 **`MENU ＋ 放大鏡`** 才會叫出選單（若完全沒碰過螢幕就直接長按組合鍵，模組尚未載入，選單不會出現）。
2. **按鍵與觸控操作**
   - 本選單採**事件透傳**設計，不會攔截 Sony 原生按鍵與觸控；建議在**正常 Live View 拍攝待機畫面**召喚並點擊選單，避免背景誤觸原生深層選單或對焦點。
   - 所有設定皆保存於 RAM，**關機或拔電池後會自動重設為 `關閉`**，不寫入相機 Flash。
3. **單一資料夾 `.JPG` 張數限制（重要）**
   - 最新一個 `DCIM` 日期資料夾（例如 `10261117`）內的 **`.JPG` 總數不可達到 `128` 張**（`.ARW` RAW 檔不計入）。
   - 若張數接近 120 張，請在相機選單中建立新的儲存資料夾，或等待隔日自動換新資料夾。
4. **單張原片 `.JPG` 檔案大小限制**
   - 單張待處理的 `.JPG` 須小於 **`16,711,680 bytes`（約 `15.94 MiB` / `16.7 MB`）**。
   - 使用 `精細（FINE）` 畫質幾乎不會超過；若使用 `超精細（X.FINE）` 拍攝細節極多或高 ISO 場景導致原圖超過此上限，該張會自動略過濾鏡處理（原片不會受損）。
5. **作業進行中勿立即切換設定**
   - 拍完一張開啟濾鏡的照片後，背景需約 20–22 秒完成讀取、運算、寫入與讀回驗證。這段期間請勿切換「開啟／關閉」或更換風格，否則當筆作業會依安全規則取消該張輸出。
6. **SD 卡管理注意事項**
   - **不可刪除 `/A6400/TEST/` 目錄**：每次格式化記憶卡或更換新記憶卡後，請先建立空的 `/A6400/TEST/` 資料夾再拍照。
   - **未插卡開機**：沒有插 SD 卡時開機不會變磚，選單仍能開啟；但背景守護行程在等待 **`60` 秒**仍未偵測到記憶卡後會自行安全退出，若超過 60 秒後才補插記憶卡，須重新開機才會恢復自動套色。

## 五、緊急停用與版本回滾

- **臨時停用（不刪除檔案）**：
  - 透過 PMCA 在相機建立 `/tmp/disable_hook` 空檔案，下次冷開機即會在最前端跳過所有外掛流程，完全恢復原廠行為（刪除該檔即可恢復）。
- **版本回滾**：
  - 透過 PMCA 將部署前備份的 `/tmp/autoexec.sh.pre-backup` 與 `/tmp/a6400-film-boot-v15.tar.pre-backup` **成對還原**覆蓋回 `/tmp/` 並核對 `sha256sum`，之後斷電重開機即可。
